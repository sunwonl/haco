# [IR-016] Design Reviewer (DR) 활성화 및 ValidationTool 구현

**날짜**: 2026-04-12  
**단계**: Phase 5.5 — 설계 검증 프로세스 내재화

---

## 구현 배경

시스템 설계(SA)와 실제 구현(CD) 사이에 기술적인 검토 단계를 추가하여, 잘못된 데이터 스키마나 기획 의도와 맞지 않는 설계가 구현 단계로 넘어가는 것을 방지하고자 했습니다. 이를 위해 "설계 리뷰어(Design Reviewer)" 에이전트를 활성화하고 전용 검증 도구를 부여했습니다.

---

## 구현 내용

### 1. `ValidationTool` 개발 (`tools/validation.py`)
- **`validate_schema(file)`**: Pydantic/SQLAlchemy 등 전문 모델 파일에 대해 `ruff`를 활용한 정적 분석을 수행합니다.
- **`check_architecture_sync()`**: `arch_notes.md`에 명시된 파일 목록이 실제 파일 시스템과 일치하는지(누락되거나 빈 파일은 없는지) 자동 체킹합니다.

### 2. Design Reviewer 에이전트 활성화 (`agents/dr.py`)
- **핵심 역할**: SA가 작성한 설계 문서를 기술적으로 분석하고, 자동 검증 도구 결과를 통합하여 "PASS" 또는 "REVISE"를 결정합니다.
- **피드백 루프**: 설계 결함 발견 시 반려(`REVISE`) 처리를 통해 SA에게 구체적인 수정 요청을 보냅니다.

### 3. 오케스트레이션 그래프 통합 (`graph.py`)
- 기존의 더미(Dummy) 노드를 제거하고 실제 `dr_node`를 LangGraph에 연동했습니다.
- 이제 PO가 설계를 위해 SA를 호출한 후, 구현(CD)으로 넘어가기 전 반드시 DR의 검토를 거치는 워크플로우를 구성할 수 있습니다.

---

## 검증 결과

- **그래프 컴파일 성공**: 모든 에이전트 노드가 정상적으로 연결되었음을 확인했습니다.
- **자동 동기화 체크**: `ValidationTool`이 `arch_notes.md` 내용을 파싱하여 누락된 파일을 보고하는 기능을 확인했습니다.

---

## 향후 계획

- **PRD 대조 강화**: `ValidationTool`에 LLM 기반의 요구사항-설계 일치성 비교 기능을 추가하여 정성적 리뷰를 보강할 예정입니다.
