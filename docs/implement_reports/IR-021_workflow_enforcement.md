# [IR-021] 워크플로 강제 및 루프 방지 지침 고도화

**날짜**: 2026-04-13  
**단계**: Phase 5.8 — 신뢰성 및 핸드오프 최적화

---

## 구현 배경

이전 실행에서 PO(Product Owner)와 SA(System Architect) 간에 역할 경계가 모호하여 무한 루프가 발생하고, 10회의 재귀 제한에 도달하는 문제가 발견되었습니다. 이를 해결하기 위해 에이전트 분류 체계(Planner, Generator, Reviewer)를 지침에 명문화하고 엄격한 단계별 전이 규칙을 적용했습니다.

---

## 주요 구현 내용

### 1. 지침 고도화 (`.harness/instructions/`)

*   **PO (Planner/Supervisor)**:
    *   **Planner -> Generator -> Reviewer** 파이프라인을 엄격히 준수하도록 명시.
    *   SA(Planner)에게 같은 작업에 대해 2회 이상 보충 설명을 요구하지 않도록 제한.
    *   설계안(`arch_notes.md`)이 존재하면 즉시 CD/UI(Generator)에게 권한을 넘기도록 지시.
*   **System Architect (Planner)**:
    *   설계 완료 시 "설계가 완료되어 구현 준비가 되었다"는 명시적인 선언을 하도록 유도.
    *   추상적인 요약보다 구체적인 파일 구조 및 사양 정의에 집중하도록 개선.
*   **Core Developer (Generator)**:
    *   준비된 설계안이 있을 경우 즉시 구현권(Ownership)을 가지고 작업을 주도하도록 지침 보강.

### 2. 프로젝트 설정 최적화 (`settings.json`)

*   **`max_iterations` 상향**: 복잡한 다중 에이전트 협업 환경에서 충분한 턴(Turn)을 확보하기 위해 재귀 제한을 **10회 → 30회**로 상향 조정했습니다.

---

## 기대 효과

*   **루프 방지**: 에이전트들이 "다음은 누구의 차례인가"에 대해 더 명확하게 인지하므로 중복 호출이 줄어듭니다.
*   **안정적인 완료**: 30회의 턴을 통해 설계, 구현, 검증, 수정으로 이어지는 긴 워크플로를 중단 없이 마칠 수 있습니다.
*   **역할군 명확화**: Planner(설계), Generator(생성), Reviewer(검토)의 책임 범위가 명확해져 협업 효율이 증대됩니다.
