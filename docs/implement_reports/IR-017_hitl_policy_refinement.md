# [IR-017] HITL (Human-In-The-Loop) 정책 최적화

**날짜**: 2026-04-12  
**단계**: Phase 5 보완 — 사용자 경험(UX) 개선

---

## 구현 배경

기존 시스템은 모든 워크플로우의 시작점인 `PO` 노드 진입 전 항상 중단점(Interrupt)이 발생했습니다. 이는 단순 질문(Inquiry)이나 인사(Conversation) 같은 읽기 위주의 작업에서도 매번 사용자의 승인을 요구하여 사용성을 저해하는 요인이 되었습니다.

---

## 변경 내용

### 1. 중단점 노드 변경 (`graph.py`)
- **이전**: `interrupt_before=["PO"]`
- **변경**: `interrupt_before=["Design Reviewer", "Core Developer", "UI Engineer"]`
  - **PO/SA 노드**: 사용자 승인 없이 즉시 실행됩니다. 이를 통해 파일 조회, 상태 분석 등의 읽기 작업이 중단 없이 빠르게 완료됩니다.
  - **DR/CD/UI 노드**: 실제 설계가 확정되거나 코드가 작성되기 직전에는 반드시 사용자의 검토를 거칩니다.

### 2. 기대 효과
- **읽기 작업 고속화**: "현재 파일 구조 보여줘", "이 코드 분석해줘" 등의 요청에 대해 승인 프롬프트 없이 즉각적인 답변을 받을 수 있습니다.
- **안전한 실행**: 실제 파일 수정이 예고된 시점(Design Reviewer 승인 단계)에서는 여전히 중단점이 작동하여 안전성을 유지합니다.

---

## 검증 결과

- **Inquiry 테스트**: "ls -R" 요청 시, 중단 없이 결과가 바로 출력됨을 확인.
- **Implementation 테스트**: 프로젝트 생성 요청 시, SA가 설계를 마친 후 DR 노드 진입 직전에 `Approval >` 프롬프트가 정상적으로 뜨는 것을 확인.
