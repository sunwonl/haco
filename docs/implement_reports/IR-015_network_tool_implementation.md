# [IR-015] NetworkTool 구현 및 QA 에이전트 바인딩

**날짜**: 2026-04-12  
**단계**: Phase 5.5 — 검증 지능 고도화

---

## 구현 배경

기존 QA 에이전트는 코드의 텍스트만 보고 "정성적"으로 판단하거나, CD 에이전트가 남긴 테스트 결과에만 의존했습니다. 실제 서버가 떠 있는지, API 엔드포인트가 올바른 응답을 주는지 확인하는 "런타임 검증" 능력이 필요했습니다.

---

## 구현 내용

### 1. `NetworkTool` 클래스 개발 (`tools/network.py`)
- **`ping(url)`**: 특정 URL의 가용성 및 응답 시간을 확인합니다. 로컬 서버(localhost:8000 등)가 정상 작동하는지 체크할 때 사용합니다.
- **`http_request(method, url, data)`**: GET/POST 등의 실제 HTTP 요청을 보내고 응답 본문(JSON 등)을 파싱하여 반환합니다. 

### 2. QA 에이전트 통합 (`agents/qa.py`)
- **Proactive Verification**: 이제 QA 노드는 실행 시 자동으로 다음을 수행합니다.
  - 현재 백그라운드에서 실행 중인 프로세스 목록(`ProcessControlTool`) 확인.
  - 관련 엔드포인트(예: FastAPI 프로젝트의 경우 `/health`)에 대한 자동 `ping` 테스트.
- **컨텍스트 강화**: 위 검증 결과를 LLM 프롬프트에 포함하여, "서버가 정상적으로 응답하지 않음"과 같은 실제 런타임 이슈를 기반으로 승인/반려를 결정하게 했습니다.

---

## 검증 결과

- **`urllib` 기반 안정성**: 외부 라이브러리 의존 없이 표준 라이브러리만으로 범용적인 HTTP 통신 기능을 확보했습니다.
- **QA 판단 근거 강화**: "코드는 맞아 보이지만, 서버가 8000번 포트에서 응답하지 않습니다"와 같은 구체적인 반려 피드백이 가능해졌습니다.
