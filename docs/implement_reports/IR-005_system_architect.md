# [IR-005] System Architect 에이전트 구현 및 전문 에이전트 그룹 인격화

**날짜**: 2026-04-12  
**단계**: Phase 2 — 전문 에이전트 실구현 및 상호작용성 강화

---

## 구현 배경

1. **코드 분석 능력**: 에이전트가 단순한 프롬프트 처리를 넘어 현재 프로젝트의 파일 구조를 파악하고, 기존 코드를 분석하여 설계를 제안할 수 있는 기능이 필요했습니다.
2. **에이전트별 일관된 인터페이스**: 모든 에이전트(SA, CD, UI, QA)가 단순히 기술적인 로그를 남기는 것을 넘어, 사용자에게 자신의 작업 내용을 한글(또는 지정된 언어)로 친절하게 설명하는 '인격화된' 소통 방식이 요구되었습니다.

---

## 구현 내용

### 1. System Architect (SA) 실구현 (`sa.py`)
- **코드베이스 탐색**: `FileIOTool`을 사용하여 프로젝트 루트의 파일 목록을 읽고, 관련 키워드로 코드를 검색하는 기능을 탑재했습니다.
- **설계 문서 작성**: 분석 결과를 `.harness/arch_notes.md` 파일에 기록하여 후속 에이전트(Core Developer, UI Engineer)가 참고할 수 있게 했습니다.
- **작업 완료 처리**: 할당된 Task ID를 인식하고 완료 상태로 업데이트합니다.

### 2. 전문 에이전트 그룹 인격화 (Conversational Transformation)
모든 전문 에이전트(`sa.py`, `cd.py`, `ui.py`, `qa.py`)의 스키마와 노드 로직을 개선했습니다.
- **`response_to_user` 필드 추가**: 각 에이전트가 사용자에게 직접 전달할 메시지를 LLM이 생성하도록 구조화된 출력을 정의했습니다.
- **REPL 연동**: 에이전트가 작업을 수행할 때마다 그 결과(details)가 REPL 화면에 사용자용 메시지로 출력되도록 `TaskLog` 연동을 마쳤습니다.
- **프롬프트 고도화**: 단순 '수행자'의 태도를 버리고 '팀원'으로서 사용자에게 친절하게 설명하도록 시스템 프롬프트를 보강했습니다.

### 3. 검증 로직 및 워크플로우 강화
- **Core Developer (CD)**: 구현 후 `pytest` 자동 실행 결과를 사용자에게 요약 보고하도록 개선.
- **QA Evaluator (QA)**: 승인/거절 시 그 이유를 기술적 로그가 아닌 사용자용 피드백으로 먼저 전달하도록 개선.

---

## 검증 결과

- **REPL 출력 확인**: `harness chat` 모드에서 SA 에이전트가 "백엔드 폴더 구조를 분석해 보니 ~한 기능들이 있네요" 와 같이 사람처럼 응답하는 것을 확인.
- **코드 연계 확인**: SA가 작성한 설계 노트를 CD 에이전트가 정상적으로 읽어오는 프로세스 확인.
